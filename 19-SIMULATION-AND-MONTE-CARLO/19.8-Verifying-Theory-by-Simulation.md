# 19.8 Verifying Theory by Simulation

[Probability](../README.md) / [Module 19: Simulation and Monte Carlo](README.md) / 19.8 Verifying Theory by Simulation

**Level:** 5 (Hero) · **Time:** about 50 minutes · **Before this:** [19.7.3 Burn-in, Mixing and Diagnostics](19.7-MCMC/19.7.3-Burn-in-Mixing-and-Diagnostics.md)

> **Big idea:** A formula and a simulation are two independent witnesses; compute the distance between them in standard errors (the z-score), and if it is small the two agree, and if it is large one of them has a bug.

---

## Why It Matters

Probability is full of answers that feel right and are wrong: the classic puzzles, the half-remembered formula, the proof with one hidden mistake. You now have the best tool against this. Before you trust any result in this book, or in your own work, write ten lines of code and test it. The same habit tests your code: a sampler that is a little off is nearly impossible to see by eye, and one comparison with the theory finds it at once. This topic turns the habit into a procedure with clear rules for when to say "agree" and when to say "bug". Use it on every problem in the practice sets of Modules 01 to 18.

## Intuition

A detective with one witness can be fooled. With two witnesses who know nothing about each other, a match is strong evidence, and a mismatch means someone is lying or mistaken. Theory and simulation are two such witnesses. Theory comes from algebra and reasoning. Simulation comes from brute force. They fail in different ways, so when they agree, you can trust both.

But how close is "agree"? The simulation is random, so it never matches exactly. The answer is to measure the gap in units of its own noise. If the simulation says $0.5169$ with a standard error of $0.0011$, and the theory says $0.5177$, the gap is $0.0008$, less than one standard error: agree. If the theory says $0.6667$, the gap is $134$ standard errors: not noise. Something is wrong, and the simulation is almost certainly the one that is right (if the code is correct).

## Picture

```text
     DISAGREE     re-run         fine: noise         re-run     DISAGREE
                  bigger n                           bigger n
  <-------------+----------+-----------------------+----------+------------>
               -3         -2          0           +2         +3          z

  z = (simulation - theory) / standard error
```

Noise alone gives $\lvert z \rvert \lt 2$ about 95% of the time and $\lvert z \rvert \gt 3$ about 0.3% of the time.

## Definition

Let $\hat{\theta}$ be a Monte Carlo estimate with standard error $\operatorname{SE}$ ([19.3](19.3-Monte-Carlo-Estimation.md)), and let $\theta_0$ be the value predicted by the theory. The **z-score of the check** is

$$
z = \frac{\hat{\theta} - \theta_0}{\operatorname{SE}}
$$

**In words:** how many standard errors the simulation is away from the theory.

The **verification procedure** has six steps:

1. State the exact value $\theta_0$ from the theory, and say what the code must compute.
2. Write the simulation with a seeded generator and enough trials for a small standard error.
3. Compute $\hat{\theta}$ and its standard error.
4. Compute $z$. If $\lvert z \rvert \lt 2$, the check passes. If $2 \le \lvert z \rvert \lt 3$, repeat with 4 times more trials. If $\lvert z \rvert \ge 3$, there is a disagreement.
5. On a disagreement, look for the bug in both witnesses: the code first (is it the same experiment?), then the theory.
6. Repeat with another seed. A real error does not go away.

To check a whole **distribution**, not just one number, use one of two classic distances.

- **Kolmogorov-Smirnov distance** (for a continuous law with CDF $F$). With the empirical CDF $\hat{F}_n(x)$ (the fraction of the $n$ sample values that are at most $x$),

$$
D_n = \max_x \lvert \hat{F}_n(x) - F(x) \rvert
$$

For a correct sampler, $\sqrt{n} D_n$ stays below $1.358$ in 95% of runs (a standard fact of statistics; the value comes from the Kolmogorov distribution).

- **Chi-square statistic** (for a discrete law with $k$ values). With observed counts $O_i$ and expected counts $E_i = n p_i$,

$$
\chi^2 = \sum_{i=1}^{k} \frac{(O_i - E_i)^2}{E_i}
$$

For a correct sampler, $\chi^2$ follows approximately the chi-square law with $k - 1$ degrees of freedom ([9.6](../09-CONTINUOUS-DISTRIBUTIONS/9.6-Chi-Square-Student-t-and-F.md)). For a die ($k = 6$) it stays below $11.07$ in 95% of runs.

## Why It Is True

**The z-score is a standard normal when the theory is right.** The estimate $\hat{\theta}$ is an average of i.i.d. values, so by the Central Limit Theorem ([17.5](../17-LIMIT-THEOREMS/17.5-Central-Limit-Theorem.md)) it is close to $\mathcal{N}(\theta_0, \operatorname{SE}^2)$ when $\theta_0$ is the truth. Then $z \approx \mathcal{N}(0, 1)$, and

$$
P(\lvert z \rvert \gt 2) \approx 0.0455, \qquad P(\lvert z \rvert \gt 3) \approx 0.0027
$$

So a value of $\lvert z \rvert \gt 3$ almost never comes from noise.

**A real error grows with the number of trials.** Suppose the theory is off by $\delta$, so the true value is $\theta_0 + \delta$. Then $\hat{\theta} \approx \theta_0 + \delta$ and $\operatorname{SE} = \frac{\sigma}{\sqrt{n}}$, so

$$
z \approx \frac{\delta}{\sigma / \sqrt{n}} = \frac{\delta \sqrt{n}}{\sigma}
$$

This grows like $\sqrt{n}$. Four times more trials double a real discrepancy's $z$, while a noise value of $z$ stays about the same size. That is why step 4 says to repeat with more trials. It also says how small an error a simulation can find: about $\frac{3\sigma}{\sqrt{n}}$.

**Many checks give some false alarms.** If you run 20 independent checks and flag everything with $\lvert z \rvert \gt 2$, the chance of at least one false alarm is $1 - 0.9545^{20} = 0.61$. With the limit $3$ it is $1 - 0.9973^{20} = 0.05$. Use the limit $3$ for a batch of checks, and treat a value between 2 and 3 as a reason to re-run.

**Agreement is not proof.** If the theory and the code come from the same wrong idea (both assume independence, say), they will agree and both be wrong. The witnesses must be built independently, and the simulation should follow the story of the problem literally (roll the dice, draw the cards), not the formula.

## Worked Examples

### Example 1: The Birthday Problem

**Problem.** In a class of 23 people, with 365 equally likely birthdays, what is the probability that two share a birthday? Check it by simulation.

**Solution.**

1. Theory ([2.11.1](../02-COUNTING/2.11-Classic-Counting-Problems/2.11.1-Birthday-Problem.md)): count the no-match case. The $i$-th person (for $i = 0, \dots, 22$) must avoid the $i$ birthdays already taken:

$$
P(\text{no match}) = \prod_{i=0}^{22} \frac{365 - i}{365} = 0.4927 \quad \Rightarrow \quad P(\text{match}) = 1 - 0.4927 = 0.5073
$$

2. Simulation: draw $23$ birthdays (whole numbers from 0 to 364), sort them, and check whether two neighbours are equal. Repeat 200,000 times.
3. The standard error is $\sqrt{\frac{0.507 \times 0.493}{200{,}000}} = 0.0011$.

**Answer.** The theory gives $0.5073$. The simulation gives $0.5072 \pm 0.0011$, so $z = -0.1$.

**Check.** The gap is a tenth of a standard error: the witnesses agree. A class of 23 people has a better than even chance of a shared birthday.

### Example 2: Gambler's Ruin

**Problem.** You start with 3 taka and bet 1 taka on a fair coin until you have 10 taka or 0 taka. The theory ([18.2.2](../18-STOCHASTIC-PROCESSES/18.2-Random-Walks/18.2.2-Gamblers-Ruin.md)) says $P(\text{reach } 10) = \frac{3}{10}$. Check it.

**Solution.**

1. Simulate 200,000 gamblers at once. At each round, every gambler who still plays gets $+1$ or $-1$. Stop when nobody is still playing.
2. Record $I = 1$ if the gambler ends with 10 taka. The estimate is the average of $I$.
3. The standard error is $\sqrt{\frac{0.3 \times 0.7}{200{,}000}} = 0.0010$.

**Answer.** The simulation gives $0.2990 \pm 0.0010$ against the theory $0.3000$, so $z = -1.0$: they agree.

**Check.** The simulated gap $0.0010$ is one standard error. This passes (step 4 asks for a re-run only when $\lvert z \rvert \ge 2$).

### Example 3: Catching a Wrong Claim

**Problem.** A friend says: the chance of at least one six in 4 rolls of a die is $\frac{4}{6}$, because each roll gives a six with probability $\frac{1}{6}$ and there are 4 rolls. Test the claim, and find the right answer.

**Solution.**

1. The claim is $\theta_0 = \frac{4}{6} = 0.6667$.
2. Simulate 200,000 sets of 4 rolls and record whether a six appears. The estimate is $0.5169$ with standard error $0.0011$.
3. $z = \frac{0.5169 - 0.6667}{0.0011} = -134$. This is not noise. The claim is wrong.
4. The mistake: the events "six on roll 1", "six on roll 2", ... overlap, so adding their probabilities counts the overlaps twice (the union bound, [3.6](../03-AXIOMS-OF-PROBABILITY/3.6-Union-Bound.md), is only an upper bound). The right method uses the complement: no six in all 4 rolls has probability $\left( \frac{5}{6} \right)^4 = 0.4823$.

**Answer.** $P(\text{at least one six}) = 1 - \left( \frac{5}{6} \right)^4 = 0.5177$. The simulation $0.5169 \pm 0.0011$ gives $z = -0.8$ against this.

**Check.** One simulation run rejects the wrong claim and accepts the right one. This is the famous puzzle of the Chevalier de Mere in the 1650s, who lost money by betting with the wrong number.

### Example 4: Catching a Bug in a Sampler

**Problem.** A student writes `rng.integers(1, 6)` to roll a die, and uses 6,000 rolls. A second student uses `rng.integers(1, 7)`. Which is right? Use the chi-square statistic. Also test an exponential sampler with rate 2 that has a typing mistake: the code divides by 2.1.

**Solution.**

1. For a fair die with 6,000 rolls, each face is expected $E_i = 1000$ times. The 95% limit of $\chi^2$ with 5 degrees of freedom is $11.07$.
2. In numpy the upper end of `integers(low, high)` is **excluded**, so `integers(1, 6)` gives only the faces 1 to 5. Face 6 never appears. Then each of the five faces has about 1200 counts, and $\chi^2 \approx 5 \cdot \frac{200^2}{1000} + \frac{1000^2}{1000} = 200 + 1000 = 1200$.
3. For the exponential sampler, compare its empirical CDF with the exact $F(x) = 1 - e^{-2x}$ using $\sqrt{n} D_n$ with $n = 100{,}000$ and the limit $1.358$.

**Answer.** `integers(1, 7)` gives $\chi^2 = 8.3$ (below $11.07$): fine. `integers(1, 6)` gives $\chi^2 = 1203.0$: broken. The correct exponential sampler has $\sqrt{n} D_n = 0.95$ (below $1.358$), and the sampler with 2.1 has $6.41$: broken.

**Check.** A wrong rate of 2.1 instead of 2 is a 5% error. It is invisible in a histogram, but the distance test finds it easily with 100,000 samples, because the real error grows like $\sqrt{n}$.

## Simulate It

First, the checks of Examples 1 to 3 with one helper function that prints the $z$-score:

```python
import numpy as np

rng = np.random.default_rng(42)

def check(name, estimate, std_error, exact):
    z = (estimate - exact) / std_error                  # how many standard errors off?
    verdict = "OK" if abs(z) < 3 else "DISAGREE"
    print(f"{name:<16} {estimate:.4f} +- {std_error:.4f} | exact {exact:.4f} | z {z:+.1f} {verdict}")

def mc(indicator):
    p = indicator.mean()
    return p, np.sqrt(p * (1 - p) / len(indicator))

n_trials = 200_000

# 1. Birthday problem: some match among 23 people.
days = np.sort(rng.integers(0, 365, size=(n_trials, 23)), axis=1)
has_match = (np.diff(days, axis=1) == 0).any(axis=1)
exact_birthday = 1 - np.prod((365 - np.arange(23)) / 365)
check("birthday, 23", *mc(has_match), exact_birthday)

# 2. Gambler's ruin: start with 3, stop at 0 or 10, fair coin. Exact P(reach 10) = 3/10.
money = np.full(n_trials, 3)
while True:
    playing = (money > 0) & (money < 10)
    if not playing.any():
        break
    money[playing] += rng.choice([-1, 1], size=playing.sum())
check("ruin, 3 to 10", *mc(money == 10), 0.3)

# 3. At least one six in 4 rolls: the correct theory, and a common wrong claim.
rolls = rng.integers(1, 7, size=(n_trials, 4))
one_six = (rolls == 6).any(axis=1)
check("six in 4 rolls", *mc(one_six), 1 - (5 / 6) ** 4)
check("wrong claim 4/6", *mc(one_six), 4 / 6)
```

Output:

```text
birthday, 23     0.5072 +- 0.0011 | exact 0.5073 | z -0.1 OK
ruin, 3 to 10    0.2990 +- 0.0010 | exact 0.3000 | z -1.0 OK
six in 4 rolls   0.5169 +- 0.0011 | exact 0.5177 | z -0.8 OK
wrong claim 4/6  0.5169 +- 0.0011 | exact 0.6667 | z -134.1 DISAGREE
```

Now the distribution checks of Example 4:

```python
import numpy as np
from scipy.stats import chi2, kstwobign

rng = np.random.default_rng(42)
n = 100_000

def ks_distance(sample, cdf):
    # Largest gap between the empirical CDF and the exact CDF.
    x = np.sort(sample)
    f = cdf(x)
    upper = np.arange(1, n + 1) / n - f
    lower = f - np.arange(0, n) / n
    return max(upper.max(), lower.max())

crit = kstwobign.ppf(0.95)                               # 5% limit for sqrt(n) * D, about 1.358
rate = 2.0
cdf = lambda x: 1 - np.exp(-rate * x)
good = -np.log(1 - rng.random(n)) / rate                 # correct inverse transform
bad = -np.log(1 - rng.random(n)) / 2.1                   # wrong rate: a 5% mistake
for name, sample in [("correct sampler", good), ("rate 2.1 instead", bad)]:
    stat = np.sqrt(n) * ks_distance(sample, cdf)
    print(f"{name:<17} sqrt(n) D = {stat:5.2f} (limit {crit:.3f})  {'OK' if stat < crit else 'DISAGREE'}")

# Chi-square test of a die: a good die, and a die made with the common off-by-one bug.
limit = chi2.ppf(0.95, df=5)
for name, rolls in [("integers(1, 7)", rng.integers(1, 7, 6_000)), ("integers(1, 6)", rng.integers(1, 6, 6_000))]:
    counts = np.bincount(rolls, minlength=7)[1:]
    stat = ((counts - 1_000) ** 2 / 1_000).sum()
    print(f"{name:<17} chi-square = {stat:7.1f} (limit {limit:.2f})  {'OK' if stat < limit else 'DISAGREE'}")
```

Output:

```text
correct sampler   sqrt(n) D =  0.95 (limit 1.358)  OK
rate 2.1 instead  sqrt(n) D =  6.41 (limit 1.358)  DISAGREE
integers(1, 7)    chi-square =     8.3 (limit 11.07)  OK
integers(1, 6)    chi-square =  1203.0 (limit 11.07)  DISAGREE
```

Both broken samplers are found at once, and the correct ones pass.

## Common Mistakes

- **Comparing without a standard error.** "The simulation gives 0.4963 and the theory 0.5, so it works" means nothing unless you know that the noise is about $0.0005$ or about $0.05$. Always compute $z$.
- **Accepting a pass from a tiny simulation.** With 100 trials, only huge errors can be seen. Choose $n$ large enough that an error you care about would give $\lvert z \rvert \gt 3$: about $\frac{3\sigma}{\sqrt{n}}$.
- **Changing the seed until the check passes.** A check that passes for one seed in five is a failure. Fix the seed in advance, and re-run with others as a test, not as a way to pick a result.
- **Building the simulation from the formula instead of the story.** If the code computes $1 - (\frac{5}{6})^4$ it proves nothing. The code must roll four dice and look for a six.
- **Off-by-one and boundary errors in code.** `integers(1, 6)` excludes 6. A test `x < t` and a test `x <= t` are the same for continuous laws but different for discrete ones. These bugs give small, steady errors that a $z$-score or a chi-square test finds.

## Where It Is Used

- **AI and machine learning:** unit tests for probabilistic code compare the sample mean and variance of a layer or a sampler with the exact values. Researchers test a new MCMC or importance sampling code on a target with a known answer before using it on a real model.
- **Computer science:** testing a randomized algorithm (does the hash spread keys uniformly?) with the chi-square statistic, and checking a random number generator with batteries of such tests.
- **Statistics and science:** a simulation study checks that a confidence interval covers the truth 95% of the time ([19.3](19.3-Monte-Carlo-Estimation.md)), and that a test has the claimed error rate.
- **Finance and engineering:** a pricing code is checked against the closed form in the special case where one exists, before it is trusted in the cases where none does.
- **Everyday life:** before believing a surprising claim about odds, whether in a game, a news report or a casino, simulate the story in a few lines.

## Practice

**1. (Easy)** A simulation of the gambler's ruin gives $0.2990$ with standard error $0.0010$. The theory is $0.3000$. Find $z$ and decide.

<details>
<summary>Answer</summary>

$$z = \frac{0.2990 - 0.3000}{0.0010} = -1.0$$

Since $\lvert z \rvert \lt 2$, the check passes: the gap is within normal noise.

</details>

**2. (Easy)** You run 20 independent checks and flag any with $\lvert z \rvert \gt 2$. Even if all the theories are correct, what is the chance of at least one false alarm? What if you use the limit 3 instead?

<details>
<summary>Answer</summary>

For one check, $P(\lvert z \rvert \gt 2) \approx 0.0455$ and $P(\lvert z \rvert \gt 3) \approx 0.0027$. For 20 independent checks:

$$1 - (1 - 0.0455)^{20} \approx 0.61, \qquad 1 - (1 - 0.0027)^{20} \approx 0.05$$

So with the limit 2 you see a false alarm in about 6 batches out of 10, and with the limit 3 only in about 1 batch out of 20.

</details>

**3. (Medium)** A true probability near $0.5$ is $0.002$ higher than the theory says. How many trials do you need before the simulation shows $z = 3$?

<details>
<summary>Answer</summary>

With $\sigma = 0.5$, $z = \frac{\delta \sqrt{n}}{\sigma}$. Set $z = 3$ and solve for $n$:

$$n = \left( \frac{3 \sigma}{\delta} \right)^2 = \left( \frac{3 \times 0.5}{0.002} \right)^2 = 750^2 = 562{,}500$$

A small error needs a large simulation to be seen.

</details>

**4. (Medium)** Chevalier de Mere also bet on at least one double six in 24 throws of two dice. The exact probability is $1 - (\frac{35}{36})^{24} = 0.4914$. With 25 throws it is $1 - (\frac{35}{36})^{25} = 0.5055$. About how many simulated trials are needed before the gap $0.0141$ between them is 3 standard errors of one estimate? Use $\sigma \approx 0.5$.

<details>
<summary>Answer</summary>

We need $\frac{0.0141}{\operatorname{SE}} = 3$, so $\operatorname{SE} = 0.0047$. Since $\operatorname{SE} = \frac{0.5}{\sqrt{n}}$:

$$n = \left( \frac{0.5}{0.0047} \right)^2 = \left( \frac{3 \times 0.5}{0.0141} \right)^2 \approx 11{,}300$$

This shows why the gambler could see the difference only after thousands of games, and why he did not.

</details>

**5. (Hard)** Suppose the theory value is $\theta_0$ but the true value is $\theta_0 + \delta$. Show that $z \approx \frac{\delta \sqrt{n}}{\sigma}$ and explain why quadrupling $n$ doubles $z$ for a real discrepancy but leaves the noise size unchanged.

<details>
<summary>Answer</summary>

By the Law of Large Numbers, $\hat{\theta} \to \theta_0 + \delta$, and the standard error is $\operatorname{SE} = \frac{\sigma}{\sqrt{n}}$. So

$$z = \frac{\hat{\theta} - \theta_0}{\sigma / \sqrt{n}} \approx \frac{\delta}{\sigma / \sqrt{n}} = \frac{\delta \sqrt{n}}{\sigma}$$

Replacing $n$ by $4n$ replaces $\sqrt{n}$ by $2\sqrt{n}$, so a real discrepancy doubles its $z$. If $\delta = 0$, then by the Central Limit Theorem $z \approx \mathcal{N}(0, 1)$ for every $n$, so its typical size does not depend on $n$. That is why a large $z$ that keeps growing is an error and a large $z$ that disappears with more trials was noise.

</details>

**6. (Simulate)** Let $M = \max(U_1, U_2)$ for two independent uniform numbers. The theory says $E[M] = \frac{2}{3}$ and $P(M \le 0.5) = \frac{1}{4}$. Check both with 100,000 trials and report $z$.

<details>
<summary>Answer</summary>

```python
import numpy as np

rng = np.random.default_rng(42)
n = 100_000
m = np.maximum(rng.random(n), rng.random(n))
for name, values, exact in [("E[max]", m, 2 / 3), ("P(max <= 0.5)", (m <= 0.5).astype(float), 0.25)]:
    est = values.mean()
    se = values.std(ddof=1) / np.sqrt(n)
    print(f"{name:<14} {est:.4f} +- {se:.4f} | exact {exact:.4f} | z {(est - exact) / se:+.1f}")
```

Output:

```text
E[max]         0.6663 +- 0.0007 | exact 0.6667 | z -0.4
P(max <= 0.5)  0.2512 +- 0.0014 | exact 0.2500 | z +0.9
```

Both $z$ values are below 2, so both theories pass. (The theory: $P(M \le t) = t^2$, so the density is $2t$ and $E[M] = \int_0^1 t \cdot 2t \thinspace dt = \frac{2}{3}$.)

</details>

## Summary

- Theory and simulation are two independent witnesses. Compare them with the $z$-score $z = \frac{\hat{\theta} - \theta_0}{\operatorname{SE}}$.
- If $\lvert z \rvert \lt 2$ the check passes. If $2 \le \lvert z \rvert \lt 3$, repeat with more trials. If $\lvert z \rvert \ge 3$ there is a disagreement: look for a bug in the code first, then in the theory.
- A real discrepancy grows like $\sqrt{n}$, while noise does not. A simulation can see errors of size about $\frac{3\sigma}{\sqrt{n}}$.
- For whole distributions use the Kolmogorov-Smirnov distance (continuous) and the chi-square statistic (discrete).
- Agreement proves nothing if the code was built from the same wrong idea. Simulate the story, not the formula.

The one formula to remember:

$$
\boxed{z = \frac{\hat{\theta} - \theta_0}{\operatorname{SE}}, \qquad \lvert z \rvert \lt 2 \text{ passes}, \quad \lvert z \rvert \ge 3 \text{ disagrees}}
$$
