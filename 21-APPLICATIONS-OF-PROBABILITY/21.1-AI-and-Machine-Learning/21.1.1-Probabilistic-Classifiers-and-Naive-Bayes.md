> **Big idea:** A probabilistic classifier turns evidence into a probability for each class with Bayes' theorem, and Naive Bayes makes this cheap by assuming the features are independent once the class is known.

---

## Why It Matters

A classifier answers questions like "is this email spam?" or "which digit is this?". A **probabilistic classifier** does more: it gives a probability for every class, so you can say "93% spam" and choose a cut-off that fits the cost of a mistake. **Naive Bayes** is the simplest and oldest example. It is just Bayes' theorem ([4.4](../../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.4-Bayes-Theorem.md)) plus one assumption from [4.9](../../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.9-Conditional-Independence.md). It trains by counting, and it shows clearly how a model, a prior and evidence combine. The next files use the same pattern with richer models.

## Intuition

Think of how you read your own inbox. An email arrives. About 4 in 10 of your emails are spam, so before reading it you already lean a little to "not spam". Then you see the word "free". Spam often contains "free", and normal mail rarely does, so your belief moves toward spam. Next you see "meeting", which is common in work mail and rare in spam, so the belief moves back. Each word pushes the belief up or down, and you add up the pushes.

Naive Bayes does exactly this. It stores, for each class, how often each word appears. To classify a new email it multiplies the prior by one factor per word, and then it rescales so that the class probabilities add up to 1. The word "naive" is honest: it treats words as separate pieces of evidence, even though words in real emails are linked. The model is wrong about this, but it is often useful anyway. Example 3 shows what the shortcut costs.

## Picture

```text
          +-------------------+
          |  class C          |        C = spam or ham
          |  prior P(C)       |
          +---------+---------+
                    |
        +-----------+-----------+-----------+
        |           |           |           |
        v           v           v           v
     +------+    +------+    +------+    +------+
     | free |    | win  |    | meet |    | rep. |   words X1 ... X4
     +------+    +------+    +------+    +------+

   Given C, the words do not depend on each other.
   Only the class points at the words.
```

The class is the common cause of the words. Once the class is known, each word needs its own small table and nothing more.

## Definition

A **classifier** maps a feature vector $\mathbf{x} = (x_1, \dots, x_d)$ to a class $C$. The **Naive Bayes model** has two parts:

- a **prior** $P(C = c)$ for each class $c$ (how common the class is);
- a **likelihood** for each feature, $P(X_i = x_i \mid C = c)$, written as if the features are **conditionally independent given the class**:

$$
P(X_1 = x_1, \dots, X_d = x_d \mid C = c) = \prod_{i=1}^{d} P(X_i = x_i \mid C = c)
$$

where $d$ is the number of features. The classifier then outputs the **posterior**:

$$
P(C = c \mid \mathbf{x}) = \frac{P(C = c) \prod_{i=1}^{d} P(X_i = x_i \mid C = c)}{\sum_{c'} P(C = c') \prod_{i=1}^{d} P(X_i = x_i \mid C = c')}
$$

**In words:** multiply the prior of each class by the likelihood of every feature value, then divide by the total over all classes so the answers add up to 1.

In the spam example the features are **word indicators**: $x_i = 1$ if word $i$ is in the email and $x_i = 0$ if it is not, so $P(X_i = 1 \mid C = c) = p_{i,c}$ is a Bernoulli probability ([7.1](../../07-DISCRETE-DISTRIBUTIONS/7.1-Bernoulli.md)). The model is **trained** by counting. If $n_c$ training emails have class $c$ and $k_{i,c}$ of them contain word $i$, the **Laplace-smoothed** estimate adds one imaginary email with the word and one without:

$$
\hat{p}_{i,c} = \frac{k_{i,c} + 1}{n_c + 2}
$$

**In words:** the share of emails of class $c$ that contain word $i$, but pulled slightly toward one half so that no probability is ever exactly 0 or 1.

## Why It Is True

**Step 1: the posterior formula.** Bayes' theorem and the law of total probability ([4.3](../../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.3-Law-of-Total-Probability.md)) give:

$$
\begin{aligned}
P(C = c \mid \mathbf{x}) &= \frac{P(\mathbf{x} \mid C = c) \thinspace P(C = c)}{P(\mathbf{x})} && \text{(Bayes)} \\
&= \frac{P(\mathbf{x} \mid C = c) \thinspace P(C = c)}{\sum_{c'} P(\mathbf{x} \mid C = c') \thinspace P(C = c')} && \text{(total probability)} \\
&= \frac{P(C = c) \prod_i P(x_i \mid C = c)}{\sum_{c'} P(C = c') \prod_i P(x_i \mid C = c')} && \text{(conditional independence)}
\end{aligned}
$$

The last line is the only place where the "naive" assumption is used. Everything else is exact.

**Step 2: why the assumption saves so much.** Without it, the likelihood $P(x_1, \dots, x_d \mid C)$ over $d$ yes/no features is a table with $2^d$ entries for each class. With $d = 20$ words this is more than a million numbers per class. With the assumption we need only $d$ numbers per class. Counting 20 numbers from a few hundred emails is easy. Counting a million numbers is not.

**Step 3: log-odds, the sum of pushes.** For two classes, spam $S$ and ham $H$, divide the two posteriors. The common denominator cancels:

$$
\ln \frac{P(S \mid \mathbf{x})}{P(H \mid \mathbf{x})} = \ln \frac{P(S)}{P(H)} + \sum_{i=1}^{d} \ln \frac{P(x_i \mid S)}{P(x_i \mid H)}
$$

**In words:** the log-odds of spam are the prior log-odds plus one push per word. The push of word $i$ is the log of how much more likely that word value is in spam than in ham. A positive push favours spam, a negative push favours ham. Logs also keep the numbers safe: a product of 2000 small probabilities underflows to 0 in a computer, but a sum of their logs does not (see "Simulate It").

**Step 4: why Laplace smoothing helps.** Suppose "meeting" never appeared in any training spam, so the plain estimate is $\hat{p} = 0$. Then every email with "meeting" has spam score exactly 0, whatever else it says. Adding the imaginary counts avoids this. It also has a clean meaning: if the unknown rate has a uniform prior $\text{Beta}(1, 1)$ and we see $k$ emails with the word out of $n$, the posterior is $\text{Beta}(1 + k, 1 + n - k)$ ([9.5](../../09-CONTINUOUS-DISTRIBUTIONS/9.5-Beta.md)), and its mean is $\frac{k + 1}{n + 2}$. So smoothing is the posterior mean of the rate.

## Worked Examples

### Example 1: Classify One Email

**Problem.** In your inbox 40% of emails are spam. For four words, the chance that the word appears in an email is:

| Word | in spam | in ham |
|---|---|---|
| free | 0.6 | 0.1 |
| win | 0.5 | 0.05 |
| meeting | 0.05 | 0.4 |
| report | 0.1 | 0.3 |

A new email contains "free" but none of the other three words. Find $P(\text{spam} \mid \mathbf{x})$.

**Solution.**

1. Write the prior: $P(S) = 0.4$ and $P(H) = 0.6$.
2. A word that is **absent** contributes the factor $1 - p$. Spam score:

$$
0.4 \times 0.6 \times (1 - 0.5) \times (1 - 0.05) \times (1 - 0.1) = 0.4 \times 0.6 \times 0.5 \times 0.95 \times 0.9 = 0.1026
$$

3. Ham score:

$$
0.6 \times 0.1 \times (1 - 0.05) \times (1 - 0.4) \times (1 - 0.3) = 0.6 \times 0.1 \times 0.95 \times 0.6 \times 0.7 = 0.02394
$$

4. Divide by the total:

$$
P(S \mid \mathbf{x}) = \frac{0.1026}{0.1026 + 0.02394} = \frac{0.1026}{0.12654} \approx 0.811
$$

**Answer.** The email is spam with probability about 0.811.

**Check.** Use log-odds. The prior gives $\ln \frac{0.4}{0.6} = -0.405$. "free" present adds $\ln \frac{0.6}{0.1} = 1.792$. "win" absent adds $\ln \frac{0.5}{0.95} = -0.642$. "meeting" absent adds $\ln \frac{0.95}{0.6} = 0.460$. "report" absent adds $\ln \frac{0.9}{0.7} = 0.251$. The total is $1.455$, and $\frac{1}{1 + e^{-1.455}} \approx 0.811$. The simulation below also gives 0.81.

### Example 2: Learn From Counts, Then Classify

**Problem.** A training set has 10 emails: 4 spam and 6 ham. The word "free" is in 3 of the spam and 1 of the ham. The word "meeting" is in 0 of the spam and 4 of the ham. Train a Naive Bayes model with Laplace smoothing, and classify an email that contains both "free" and "meeting".

**Solution.**

1. Priors from the counts: $P(S) = \frac{4}{10} = 0.4$ and $P(H) = \frac{6}{10} = 0.6$.
2. Smoothed word rates, using $\frac{k + 1}{n + 2}$:

$$
P(\text{free} \mid S) = \frac{3 + 1}{4 + 2} = \frac{2}{3}, \qquad P(\text{free} \mid H) = \frac{1 + 1}{6 + 2} = \frac{1}{4}
$$

$$
P(\text{meeting} \mid S) = \frac{0 + 1}{4 + 2} = \frac{1}{6}, \qquad P(\text{meeting} \mid H) = \frac{4 + 1}{6 + 2} = \frac{5}{8}
$$

3. Scores for an email with both words:

$$
\text{spam score} = 0.4 \times \tfrac{2}{3} \times \tfrac{1}{6} \approx 0.04444, \qquad \text{ham score} = 0.6 \times \tfrac{1}{4} \times \tfrac{5}{8} = 0.09375
$$

4. Normalize:

$$
P(S \mid \mathbf{x}) = \frac{0.04444}{0.04444 + 0.09375} \approx 0.322
$$

**Answer.** About 0.322, so the filter says "probably ham".

**Check.** Without smoothing, $P(\text{meeting} \mid S) = 0$ and the spam score would be exactly 0, so the filter would say "ham for sure" after seeing only 4 spam emails. Smoothing keeps the result honest: "free" pushes toward spam, "meeting" pushes toward ham, and ham wins by a moderate margin.

### Example 3: When the Naive Assumption Hurts

**Problem.** A careless programmer adds the feature "free" twice, so the model sees two copies of the same word. In the setting of Example 1, an email contains "free". What does Naive Bayes say, and what is the true value of $P(\text{spam} \mid \text{free})$?

**Solution.**

1. True value, one copy of the evidence:

$$
P(S \mid \text{free}) = \frac{0.4 \times 0.6}{0.4 \times 0.6 + 0.6 \times 0.1} = \frac{0.24}{0.30} = 0.8
$$

2. Naive Bayes treats the two copies as independent pieces of evidence, so it uses the factor twice:

$$
\frac{0.4 \times 0.6 \times 0.6}{0.4 \times 0.6 \times 0.6 + 0.6 \times 0.1 \times 0.1} = \frac{0.144}{0.144 + 0.006} = 0.96
$$

**Answer.** The true value is 0.8. The naive model says 0.96, which is too sure.

**Check.** Two copies of one fact are not two facts, so the evidence is counted twice. This is why Naive Bayes probabilities are often too extreme, even when its ranking of emails is good. [21.1.6](21.1.6-Uncertainty-and-Calibration.md) shows how to measure and repair this.

## Simulate It

The first part builds a world that follows the model exactly. It draws a million emails, keeps those with the pattern of Example 1, and counts the spam. The second part shows why we add logs instead of multiplying many probabilities.

```python
import numpy as np

rng = np.random.default_rng(42)
n_emails = 1_000_000

# Generative story: pick the class, then draw each word independently given the class.
p_spam = 0.4
p_word_spam = np.array([0.6, 0.5, 0.05, 0.1])   # free, win, meeting, report
p_word_ham = np.array([0.1, 0.05, 0.4, 0.3])

is_spam = rng.random(n_emails) < p_spam
p_word = np.where(is_spam[:, None], p_word_spam, p_word_ham)   # one row per email
words = rng.random((n_emails, 4)) < p_word                    # True = word present

# Condition on one pattern: "free" present, the other three words absent.
pattern = np.array([True, False, False, False])
matches = (words == pattern).all(axis=1)
estimate = is_spam[matches].mean()                            # P(spam | pattern)

# Exact Naive Bayes formula (here exact, because the model is built that way).
score_spam = p_spam * np.prod(np.where(pattern, p_word_spam, 1 - p_word_spam))
score_ham = (1 - p_spam) * np.prod(np.where(pattern, p_word_ham, 1 - p_word_ham))
exact = score_spam / (score_spam + score_ham)

print(f"Emails with this pattern: {matches.sum():,}")
print(f"Simulation: {estimate:.4f}")
print(f"Exact:      {exact:.4f}")

# Many words: the product of probabilities underflows, the sum of logs does not.
n_words = 2000
p_each = rng.uniform(0.2, 0.4, size=n_words)
print("Product of 2000 numbers:", np.prod(p_each))
print("Sum of their logs:      ", round(np.sum(np.log(p_each)), 1))
```

Output:

```text
Emails with this pattern: 127,168
Simulation: 0.8122
Exact:      0.8108
Product of 2000 numbers: 0.0
Sum of their logs:       -2436.3
```

The simulated 0.8122 agrees with the exact 0.8108 within sampling noise. The product of 2000 numbers is so small that the computer stores it as 0.0, while the sum of logs is a normal number.

## Common Mistakes

- **Forgetting the prior.** A word that is 6 times more common in spam does not make an email 6 times more likely to be spam. If spam is rare, the prior pulls the answer down. Always multiply by $P(C)$.
- **Forgetting the absent words.** Words that are not in the email also carry information, through the factor $1 - p$. In Example 1 the absent words moved the log-odds by $+0.07$ in total, so ignoring them would change the answer. (Some text models only use present words. That is a different, also valid, model.)
- **Trusting the probability too much.** Naive Bayes counts correlated words as separate evidence (Example 3), so its probabilities are often too close to 0 or 1. Use the ranking, or calibrate the output.
- **Using zero counts.** A word never seen in a class gives probability 0, and one such word cancels all other evidence. Use smoothing.
- **Multiplying many small numbers.** With hundreds of words the product underflows to 0. Add logs instead, and compare log-scores.

## Where It Is Used

- **AI and machine learning:** spam filters, document and topic classifiers, and a fast baseline for any text task. The picture of "a class that causes the features" is the simplest **Bayesian network**, a graph of variables that are conditionally independent given their causes ([4.9](../../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.9-Conditional-Independence.md)).
- **Logistic regression:** the log-odds above is a sum of weights times features. Practice problem 5 shows that Naive Bayes with yes/no features has exactly the form of logistic regression, only with its weights set by counting. [21.1.2](21.1.2-Loss-Functions-as-Probability.md) shows how the other model finds its weights.
- **Medicine:** a doctor combines a prior (how common a disease is) with several test results, as in [4.11.2 Medical Testing](../../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.11-Classic-Puzzles/4.11.2-Medical-Testing.md). See also [21.6 Medicine and Diagnostic Testing](../21.6-Medicine-and-Diagnostic-Testing.md).
- **Everyday life:** every time you update your opinion with several clues at once, you are doing a mental Naive Bayes. The warning is the same: do not count one clue twice.

## Practice

**1. (Easy)** Use the model of Example 1. An email contains only the word "win" among the four words. Do not use the other three words. Find $P(\text{spam} \mid \text{win})$ using just that one word.

<details>
<summary>Answer</summary>

The spam score is $0.4 \times 0.5 = 0.2$ and the ham score is $0.6 \times 0.05 = 0.03$:

$$P(S \mid \text{win}) = \frac{0.2}{0.2 + 0.03} = \frac{0.2}{0.23} \approx 0.870$$

</details>

**2. (Easy)** In a training set, 10 spam emails are seen and 7 of them contain "free". What is the Laplace-smoothed estimate of $P(\text{free} \mid S)$? What is the plain estimate?

<details>
<summary>Answer</summary>

The plain estimate is $\frac{7}{10} = 0.7$. The smoothed estimate adds one to the count and two to the total:

$$\hat{p} = \frac{7 + 1}{10 + 2} = \frac{8}{12} = \frac{2}{3} \approx 0.667$$

The smoothed value is a little closer to $\frac{1}{2}$.

</details>

**3. (Medium)** With the model of Example 1, an email contains "meeting" and "report" but neither "free" nor "win". Find the spam probability.

<details>
<summary>Answer</summary>

Spam score: $0.4 \times (1 - 0.6) \times (1 - 0.5) \times 0.05 \times 0.1 = 0.4 \times 0.4 \times 0.5 \times 0.05 \times 0.1 = 0.0004$.

Ham score: $0.6 \times 0.9 \times 0.95 \times 0.4 \times 0.3 = 0.06156$.

$$P(S \mid \mathbf{x}) = \frac{0.0004}{0.0004 + 0.06156} = \frac{0.0004}{0.06196} \approx 0.0065$$

The email is almost surely ham.

</details>

**4. (Medium)** You use $d = 20$ yes/no word features and two classes. How many numbers must be estimated for (a) a full joint model that stores $P(x_1, \dots, x_{20}, C)$ directly, and (b) a Naive Bayes model?

<details>
<summary>Answer</summary>

(a) The joint table has $2 \times 2^{20} = 2^{21}$ cells, and they must add to 1, so $2^{21} - 1 = 2{,}097{,}151$ free numbers.

(b) One prior number, and one word rate for each word and class: $1 + 2 \times 20 = 41$ numbers.

The assumption of conditional independence reduces about two million numbers to 41.

</details>

**5. (Hard)** For two classes and yes/no features, let $p_i = P(X_i = 1 \mid S)$, $q_i = P(X_i = 1 \mid H)$ and $\pi = P(S)$. Prove that the log-odds of spam is a linear function of $\mathbf{x}$: $b + \sum_i w_i x_i$. Find $w_i$ and $b$.

<details>
<summary>Answer</summary>

Because $x_i$ is 0 or 1, the push of word $i$ is $x_i \ln \frac{p_i}{q_i} + (1 - x_i) \ln \frac{1 - p_i}{1 - q_i}$. Rewrite it as a constant plus a multiple of $x_i$:

$$x_i \ln \frac{p_i}{q_i} + (1 - x_i) \ln \frac{1 - p_i}{1 - q_i} = \ln \frac{1 - p_i}{1 - q_i} + x_i \left( \ln \frac{p_i}{q_i} - \ln \frac{1 - p_i}{1 - q_i} \right)$$

Add the pushes to the prior log-odds from Step 3:

$$\ln \frac{P(S \mid \mathbf{x})}{P(H \mid \mathbf{x})} = b + \sum_{i=1}^{d} w_i x_i$$

with weights and bias

$$w_i = \ln \frac{p_i (1 - q_i)}{q_i (1 - p_i)}, \qquad b = \ln \frac{\pi}{1 - \pi} + \sum_{i=1}^{d} \ln \frac{1 - p_i}{1 - q_i}$$

This is the form of logistic regression, because the posterior is $\frac{1}{1 + e^{-(b + \sum w_i x_i)}}$.

</details>

**6. (Simulate)** Check the claim of Example 3: simulate emails, and show that among emails that contain "free", the spam fraction is about 0.8, but a model that counts "free" twice says 0.96.

<details>
<summary>Answer</summary>

```python
import numpy as np

rng = np.random.default_rng(42)
n_emails = 1_000_000

# True world: 40% spam; "free" appears in 60% of spam and 10% of ham.
is_spam = rng.random(n_emails) < 0.4
has_free = rng.random(n_emails) < np.where(is_spam, 0.6, 0.1)

# Among emails that contain "free", the true spam fraction is 0.8.
truth = is_spam[has_free].mean()

# Naive Bayes that sees "free" twice (a copy of the same feature).
score_spam = 0.4 * 0.6 * 0.6
score_ham = 0.6 * 0.1 * 0.1
naive = score_spam / (score_spam + score_ham)

print(f"True P(spam | free), simulated: {truth:.4f}")
print(f"Naive Bayes with the copy:      {naive:.4f}")
```

Output:

```text
True P(spam | free), simulated: 0.8003
Naive Bayes with the copy:      0.9600
```

</details>

## Summary

- A probabilistic classifier outputs $P(C \mid \mathbf{x})$ for every class, by Bayes' theorem: prior times likelihood, divided by the total.
- Naive Bayes assumes the features are independent given the class. Then the likelihood is a product of one small table per feature, and training is counting.
- The log-odds are the prior log-odds plus one push per feature. This form is linear, like logistic regression, and safe from underflow.
- Smoothing adds imaginary counts, and it is the posterior mean of a Beta prior. It stops a single zero from deciding everything.
- The independence assumption is often false. Then the probabilities become too extreme, though the ranking of classes can still be good.

The one formula to remember:

$$
\boxed{P(C = c \mid \mathbf{x}) \propto P(C = c) \prod_{i=1}^{d} P(X_i = x_i \mid C = c)}
$$
