> **Big idea:** Security is built on randomness that is uniform and unpredictable: a uniform $b$-bit key is guessed with probability $2^{-b}$ per try, a uniform key used once makes a message look completely random (perfect secrecy), and a key that is not uniform, or is used twice, is much weaker than its length suggests.

---

## Why It Matters

An attacker who cannot read a message tries to guess the secret instead. How hard is that? It is a probability question: what is the chance that a guess is right, and how many guesses are needed on average? The answer depends on one thing above all: whether the secret was chosen **uniformly at random**. This file shows the simplest model of a secret key, the one-time pad (the only system with a short proof of perfect secrecy), and the reason why human-chosen passwords and badly seeded generators are weak. It is a probability model only. It does not analyze any real cipher, and real security needs experts.

## Intuition

A secret key is a number the attacker does not know. If it has 3 bits, there are $2^3 = 8$ possible keys, and a random guess is right with probability $\frac{1}{8}$. Each bit doubles the number of keys, so a key with 128 bits has $2^{128}$ values, so many that guessing is hopeless even with a very fast computer. This is a counting argument, like the ones of Module 02.

There is a second idea. Suppose the message is hidden by "adding" a random key bit by bit, and each key bit is a fair coin. Then each bit of the hidden message is also a fair coin, whatever the message was. An observer sees only coin flips. The message cannot be read, not because the attacker is slow, but because the information is not there. This only works if the key is truly random, as long as the message, and never used twice.

The weak point is a key that is not uniform. If most people choose the same 100 passwords, an attacker tries these first, and succeeds much more often than $\frac{100}{\text{all passwords}}$.

## Picture

```text
  message M   =  0 1 1 0 1 0 0 1
  key K       =  1 0 1 1 0 0 1 1      uniform random bits, used ONCE
                 ---------------
  cipher C    =  1 1 0 1 1 0 1 0      C = M xor K  (add the bits, no carry)

  The attacker sees only C.  For ANY message m there is exactly one
  key that turns m into C, and every key has the same probability:

    m1 = 0 1 1 0 1 0 0 1  <-- key 1 0 1 1 0 0 1 1 --+
    m2 = 1 1 1 1 1 1 1 1  <-- key 0 0 1 0 0 1 0 1 --+--> C = 1 1 0 1 1 0 1 0
    m3 = 0 0 0 0 0 0 0 0  <-- key 1 1 0 1 1 0 1 0 --+

  So C says nothing about which message was sent.
```

The one-time pad with 8 bits. Every message is equally able to produce the cipher text $C$, each with its own key of probability $2^{-8}$.

## Definition

**The key model.** A **secret key** is a random variable $K$ that is **uniform** on all $N = 2^b$ bit strings of length $b$. An attacker who does not know $K$ makes guesses, each a different key. After $g$ guesses:

$$
P(\text{key found}) = \frac{g}{2^b}, \qquad E[\text{number of guesses until the key is found}] = \frac{2^b + 1}{2}
$$

**In words:** each guess covers $2^{-b}$ of the possible keys, and on average the attacker must search about half of the key space.

**The one-time pad.** Let $M$ be a message of $b$ bits, with any distribution. Let $K$ be uniform on $b$-bit strings and independent of $M$. The **cipher text** is $C = M \text{ xor } K$, where **xor** adds each pair of bits and drops the carry: $0 \text{ xor } 0 = 1 \text{ xor } 1 = 0$ and $0 \text{ xor } 1 = 1 \text{ xor } 0 = 1$. The system has **perfect secrecy** if the cipher text gives no information about the message:

$$
P(M = m \mid C = c) = P(M = m) \qquad \text{for all } m, c
$$

**In words:** after seeing the cipher text, the attacker believes exactly what they believed before, as if $C$ had not been seen. This means $C$ and $M$ are independent ([4.7](../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.7-Independence.md)).

**Passwords.** A password is **uniform** if it is drawn at random from a list of $N$ possibilities. A random password of length $L$ from an alphabet of $A$ symbols has $N = A^L$ possibilities, which is $\log_2 N = L \log_2 A$ bits. If the password is not uniform, the best attack tries the passwords in decreasing order of probability. If $p_{(i)}$ is the probability of the $i$-th most likely password:

$$
E[\text{guesses}] = \sum_{i=1}^{N} i \thinspace p_{(i)}
$$

**In words:** each password costs as many guesses as its rank, and the attacker pays the rank of the one that was chosen.

## Why It Is True

**Guessing a uniform key.** The events "the key equals the $j$-th guess" for $g$ different guesses are disjoint, and each has probability $2^{-b}$. By the addition rule ([3.4](../03-AXIOMS-OF-PROBABILITY/3.4-Addition-Rule.md)) the probability that one of them is right is $g \cdot 2^{-b}$. If the attacker checks all keys in some fixed order, the position $J$ of the secret in this order is uniform on $\lbrace 1, \dots, N \rbrace$, and its mean is $\frac{N + 1}{2}$. This is the same calculation as for a linear search ([21.3.3](21.3-Computer-Science/21.3.3-Average-Case-Analysis.md)).

**Perfect secrecy of the one-time pad.** Fix a message $m$ and a cipher text $c$. Then $C = c$ exactly when $K = m \text{ xor } c$ (xor with $m$ on both sides of $c = m \text{ xor } K$, using $m \text{ xor } m = 0$). So, since $K$ is independent of $M$:

$$
P(C = c \mid M = m) = P(K = m \text{ xor } c) = 2^{-b}
$$

The map $k \mapsto m \text{ xor } k$ is one-to-one, so this works for every $c$: the cipher text is uniform, whatever $m$ is. By the law of total probability, $P(C = c) = \sum_m P(M = m) \cdot 2^{-b} = 2^{-b}$. Now Bayes' theorem ([4.4](../04-CONDITIONAL-PROBABILITY-AND-BAYES/4.4-Bayes-Theorem.md)) gives:

$$
P(M = m \mid C = c) = \frac{P(C = c \mid M = m) \thinspace P(M = m)}{P(C = c)} = \frac{2^{-b} \thinspace P(M = m)}{2^{-b}} = P(M = m)
$$

**Reusing the key is fatal.** If two messages are sent with the same key, $C_1 = M_1 \text{ xor } K$ and $C_2 = M_2 \text{ xor } K$, then

$$
C_1 \text{ xor } C_2 = M_1 \text{ xor } K \text{ xor } M_2 \text{ xor } K = M_1 \text{ xor } M_2
$$

because $K \text{ xor } K = 0$. The key is gone, and the attacker sees how the two messages differ. If one message is known or guessable, the other one follows. Perfect secrecy needs a fresh key for every message, as long as the message.

**A non-uniform key is weaker.** In the proof above, $P(K = m \text{ xor } c) = 2^{-b}$ used uniformity. If the key bits are biased (for example 1 with probability $0.9$), then $P(C = c \mid M = m)$ depends on $m$, and the cipher text leaks information (problem 4).

**Guessing in order is best.** Suppose the attacker guesses password $i$ at position $i$, and two passwords at positions $i \lt j$ have $p_i \lt p_j$. Swap them. The expected number of guesses changes by $(j - i)(p_i - p_j) \lt 0$, so it falls. Hence the best order is decreasing probability, and the formula above is the smallest possible mean.

**Seeds are keys.** A pseudo-random generator ([19.2](../19-SIMULATION-AND-MONTE-CARLO/19.2-Pseudo-Random-Numbers-and-Seeds.md)) started from a seed of $s$ bits can produce only $2^s$ different streams. A key made from it has at most $s$ bits of real uncertainty, however long it is. An attacker who tries all $2^s$ seeds finds it. This is why the seeds in this book, such as 42, are for reproducible simulations and are never secrets.

**The birthday attack.** For a different goal, finding two inputs with the same $b$-bit hash value, the attacker does not need $2^b$ tries but only about $1.18 \cdot 2^{b/2}$, by the birthday problem ([21.3.2](21.3-Computer-Science/21.3.2-Hashing-and-Bloom-Filters.md)). Hash values for security need to be twice as long as keys for the same effort.

## Worked Examples

### Example 1: How Long Does a Brute-Force Search Take?

**Problem.** A random 8-character password uses 62 symbols (26 lower case letters, 26 upper case letters, 10 digits). An attacker tests $10^9$ passwords per second (a made-up speed, for the sake of the example). Find the number of possible passwords, the expected time to find it, and the same for a 128-bit key.

**Solution.**

1. The number of passwords is $62^8 = 218{,}340{,}105{,}584{,}896 \approx 2.18 \times 10^{14}$, which is $8 \log_2 62 \approx 47.6$ bits.
2. The expected number of guesses is $\frac{62^8 + 1}{2} \approx 1.09 \times 10^{14}$.
3. At $10^9$ per second: $\frac{1.09 \times 10^{14}}{10^9} = 1.09 \times 10^5$ seconds, which is about 30.3 hours.
4. A 128-bit key has $2^{128} \approx 3.4 \times 10^{38}$ values. The expected number of guesses is $\frac{2^{128} + 1}{2} \approx 1.7 \times 10^{38}$, and at the same speed this takes $1.7 \times 10^{29}$ seconds, about $5.4 \times 10^{21}$ years. The chance that a single guess is right is $2^{-128} \approx 2.9 \times 10^{-39}$.

**Answer.** About 30 hours for the random 8-character password, and about $5 \times 10^{21}$ years for the 128-bit key.

**Check.** The key has about 80 more bits than the password, so its space is about $2^{80} \approx 10^{24}$ times larger, and each extra bit doubles the work. For other lengths, the expected time at $10^9$ guesses per second is: 40 bits, about 550 seconds; 56 bits, about 1.1 years; 80 bits, about $1.9 \times 10^{7}$ years.

### Example 2: A Two-Bit One-Time Pad

**Problem.** A message has 2 bits and is either $01$ (with probability $0.9$) or $10$ (with probability $0.1$). The key $K$ is uniform on $\lbrace 00, 01, 10, 11 \rbrace$ and independent of the message. The attacker sees the cipher text $C = 11$. What is the probability that the message was $01$?

**Solution.**

1. List $C = M \text{ xor } K$ for each message and key:

| Key | $00$ | $01$ | $10$ | $11$ |
|---|---|---|---|---|
| $C$ if $M = 01$ | $01$ | $00$ | $11$ | $10$ |
| $C$ if $M = 10$ | $10$ | $11$ | $00$ | $01$ |

2. The cipher text $11$ comes from the key $10$ if the message is $01$, and from the key $01$ if the message is $10$. Each key has probability $\frac{1}{4}$, so $P(C = 11 \mid M = 01) = \frac{1}{4}$ and $P(C = 11 \mid M = 10) = \frac{1}{4}$.
3. By the law of total probability: $P(C = 11) = 0.9 \times \frac{1}{4} + 0.1 \times \frac{1}{4} = \frac{1}{4}$.
4. By Bayes' theorem:

$$
P(M = 01 \mid C = 11) = \frac{\frac{1}{4} \times 0.9}{\frac{1}{4}} = 0.9
$$

**Answer.** The probability is $0.9$, the same as before seeing $C$.

**Check.** Each of the 4 cipher texts appears once in each row of the table, so every cipher text has probability $\frac{1}{4}$ for each message. The attacker has learned nothing. If the same key were used for a second message, $C_1 \text{ xor } C_2 = M_1 \text{ xor } M_2$ would be revealed.

### Example 3: Human Passwords Are Not Uniform

**Problem.** There are 1,000 possible passwords. A random user picks the $i$-th most popular with probability proportional to $\frac{1}{i}$. An attacker tries them in decreasing order of popularity. Find the expected number of guesses, and the chance of success in 10 guesses. Compare with a uniform choice among the same 1,000.

**Solution.**

1. The probabilities are $p_{(i)} = \frac{1/i}{H_{1000}}$ with $H_{1000} = 1 + \frac{1}{2} + \dots + \frac{1}{1000} \approx 7.4855$.
2. The expected number of guesses is

$$
\sum_{i=1}^{1000} i \cdot \frac{1/i}{H_{1000}} = \frac{1000}{H_{1000}} = \frac{1000}{7.4855} \approx 133.6
$$

3. The chance of success in 10 guesses is $\frac{H_{10}}{H_{1000}} = \frac{2.9290}{7.4855} \approx 0.391$.
4. For a uniform choice the expected number of guesses is $\frac{1000 + 1}{2} = 500.5$, and the chance in 10 guesses is $\frac{10}{1000} = 0.01$.

**Answer.** About 134 guesses on average instead of 500.5, and a 39% chance of success within 10 guesses instead of 1%.

**Check.** The skewed choice is as weak as a uniform choice among only $2 \times 133.6 - 1 \approx 266$ passwords. The simulation below gives 133.4. A secret is only as strong as its distribution, not its length.

## Simulate It

Part 1 checks the one-time pad (a uniform key hides the message, a biased key does not, a reused key leaks the xor of the messages) and the brute-force probability. Part 2 checks Example 3.

```python
import numpy as np

rng = np.random.default_rng(42)
n_trials = 400_000

# One-time pad on 8-bit messages: C = M xor K, with K uniform on 0..255 and used once.
m0, m1 = 0b01101001, 0b11111111                 # two very different messages
c0 = m0 ^ rng.integers(0, 256, size=n_trials)
c1 = m1 ^ rng.integers(0, 256, size=n_trials)
freq0 = np.bincount(c0, minlength=256) / n_trials
freq1 = np.bincount(c1, minlength=256) / n_trials
print(f"Largest gap between P(C = c | m0) and 1/256: {np.abs(freq0 - 1 / 256).max():.5f}")
print(f"Largest gap between P(C = c | m1) and 1/256: {np.abs(freq1 - 1 / 256).max():.5f}")

# A BIASED key leaks: each key bit is 1 with probability 0.9 instead of 0.5.
bits = rng.random((n_trials, 8)) < 0.9
key = (bits * (2 ** np.arange(8))).sum(axis=1)
print(f"Biased key: P(C = 255 | m = 0) = {np.mean((0 ^ key) == 255):.4f}, P(C = 255 | m = 255) = {np.mean((255 ^ key) == 255):.5f}")

# Reusing the key: C1 xor C2 = M1 xor M2, whatever the key was.
key = rng.integers(0, 256, size=n_trials)
print(f"Key reused: C1 xor C2 equals M1 xor M2 in {np.mean(((m0 ^ key) ^ (m1 ^ key)) == (m0 ^ m1)):.1f} of the cases")

# Brute force on a 16-bit key: the attacker tries the keys 0, 1, ..., 999 in this order.
n_keys, n_tries = 2**16, 1000
secret = rng.integers(0, n_keys, size=n_trials)                  # uniform secret key
print(f"P(found within {n_tries} tries): simulation {np.mean(secret < n_tries):.5f}, exact {n_tries / n_keys:.5f}")
```

Output:

```text
Largest gap between P(C = c | m0) and 1/256: 0.00028
Largest gap between P(C = c | m1) and 1/256: 0.00028
Biased key: P(C = 255 | m = 0) = 0.4313, P(C = 255 | m = 255) = 0.00000
Key reused: C1 xor C2 equals M1 xor M2 in 1.0 of the cases
P(found within 1000 tries): simulation 0.01543, exact 0.01526
```

Part 2:

```python
import numpy as np

rng = np.random.default_rng(42)
n_pass, n_people = 1000, 400_000

# Human-chosen passwords: the i-th most popular is chosen with probability proportional to 1 / i.
p = 1 / np.arange(1, n_pass + 1)
p = p / p.sum()

# The attacker guesses in order of popularity, so the number of guesses equals the rank.
rank = rng.choice(n_pass, size=n_people, p=p) + 1
print(f"Skewed passwords:   mean guesses {rank.mean():.1f}, exact {np.sum(np.arange(1, n_pass + 1) * p):.1f}")
print(f"Uniform passwords:  mean guesses {(n_pass + 1) / 2:.1f}")
print(f"P(found in 10 guesses): skewed {np.mean(rank <= 10):.4f}, uniform {10 / n_pass:.4f}")
print(f"A uniform choice with the same mean would have only {2 * rank.mean() - 1:.0f} passwords")
```

Output:

```text
Skewed passwords:   mean guesses 133.4, exact 133.6
Uniform passwords:  mean guesses 500.5
P(found in 10 guesses): skewed 0.3914, uniform 0.0100
A uniform choice with the same mean would have only 266 passwords
```

With a uniform key, every cipher text is equally likely for both messages (the gaps to $\frac{1}{256} = 0.0039$ are only sampling noise). With a biased key, the cipher text $255$ appears in 43% of the cases for $m = 0$ but almost never for $m = 255$, so the attacker can tell the messages apart (the exact value is $0.9^8 \approx 0.4305$). The reused key leaks the xor in every case. The skewed passwords are found in 134 guesses on average.

## Common Mistakes

- **Thinking that a long key is a strong key.** Strength comes from uniform randomness. A key of 128 bits made from a seed of 20 bits has only 20 bits of uncertainty.
- **Reusing a one-time pad.** Then $C_1 \text{ xor } C_2 = M_1 \text{ xor } M_2$ is public. The word "once" is part of the name.
- **Assuming that people choose passwords at random.** The attacker uses the distribution of real choices. Use the expected rank $\sum i \thinspace p_{(i)}$, not $\frac{N + 1}{2}$.
- **Ignoring the base rate in alarms.** A detector that finds 99% of attacks and has a 1% false alarm rate is wrong in 99 out of 100 alarms if only 1 event in 10,000 is an attack (problem 3). The same Bayes' theorem as in [21.6](21.6-Medicine-and-Diagnostic-Testing.md).
- **Using a simulation seed as a secret.** `default_rng(42)` always gives the same numbers, so it is the opposite of unpredictable.
- **Believing that this model is the whole story.** Real systems fail through weak implementations, reused keys and human behavior, which this model does not describe.

## Where It Is Used

- **Cryptography:** the one-time pad is the model case of perfect secrecy; keys, nonces and salts are chosen uniformly at random; hash lengths follow the birthday bound.
- **Computer security:** the strength of passwords, the effort of a brute-force attack, and the number of guesses that a system allows before it blocks the user.
- **AI and machine learning:** random numbers for training are for reproducibility, and are not secrets. A privacy method adds random noise so that one person's record changes the result very little, and its guarantee is a statement about probabilities of outputs (a topic beyond this book).
- **Intrusion and fraud detection:** a Bayes' theorem calculation with a very small base rate, as in problem 3.
- **Everyday life:** a PIN with 4 digits has 10,000 values, so a guess is right with probability $\frac{1}{10{,}000}$ if it was chosen at random. A birth year is much easier to guess.

## Practice

**1. (Easy)** A key is uniform on 40 bits. What is the chance that one guess is right, and what is the expected number of guesses until the key is found?

<details>
<summary>Answer</summary>

$$P(\text{one guess is right}) = 2^{-40} \approx 9.1 \times 10^{-13}, \qquad E[\text{guesses}] = \frac{2^{40} + 1}{2} \approx 5.5 \times 10^{11}$$

At $10^9$ guesses per second (made-up speed) this is about 550 seconds.

</details>

**2. (Easy)** A random password has 8 symbols, each from the 36 symbols (26 lower case letters and 10 digits). How many passwords are there, and how many bits is that?

<details>
<summary>Answer</summary>

$$36^8 = 2{,}821{,}109{,}907{,}456 \approx 2.8 \times 10^{12}, \qquad 8 \log_2 36 \approx 41.4 \text{ bits}$$

This is about 77 times fewer than the $62^8$ passwords of Example 1.

</details>

**3. (Medium)** An alarm fires for 99% of attacks and for 1% of normal events. One event in 10,000 is an attack. Find $P(\text{attack} \mid \text{alarm})$.

<details>
<summary>Answer</summary>

$$P(\text{attack} \mid \text{alarm}) = \frac{0.0001 \times 0.99}{0.0001 \times 0.99 + 0.9999 \times 0.01} = \frac{0.000099}{0.010098} \approx 0.0098$$

Only about 1 alarm in 100 is a real attack. The alarm is good, but attacks are very rare.

</details>

**4. (Medium)** One bit of message $M \in \lbrace 0, 1 \rbrace$ is hidden with one key bit $K$ that has $P(K = 1) = 0.9$, so $C = M \text{ xor } K$. Find $P(C = 1 \mid M = 0)$ and $P(C = 1 \mid M = 1)$. If $M = 0$ and $M = 1$ are equally likely, what is $P(M = 1 \mid C = 1)$?

<details>
<summary>Answer</summary>

If $M = 0$ then $C = K$, so $P(C = 1 \mid M = 0) = 0.9$. If $M = 1$ then $C = 1$ exactly when $K = 0$, so $P(C = 1 \mid M = 1) = 0.1$. By Bayes' theorem:

$$P(M = 1 \mid C = 1) = \frac{0.1 \times 0.5}{0.1 \times 0.5 + 0.9 \times 0.5} = 0.1$$

The cipher text leaks: a prior of $0.5$ becomes $0.1$. With a fair key bit, both would be $\frac{1}{2}$.

</details>

**5. (Hard)** Prove that the one-time pad has perfect secrecy for any distribution of the message $M$, and show that reusing the key reveals $M_1 \text{ xor } M_2$.

<details>
<summary>Answer</summary>

For fixed $m$ and $c$, the event $\lbrace C = c \rbrace$ given $M = m$ is the event $\lbrace K = m \text{ xor } c \rbrace$, and $K$ is independent of $M$ and uniform on $2^b$ values:

$$P(C = c \mid M = m) = 2^{-b}$$

for every $m$ and $c$. Then $P(C = c) = \sum_m P(M = m) 2^{-b} = 2^{-b}$, and Bayes' theorem gives $P(M = m \mid C = c) = \frac{2^{-b} P(M = m)}{2^{-b}} = P(M = m)$. For two messages with the same key, $C_1 \text{ xor } C_2 = M_1 \text{ xor } K \text{ xor } M_2 \text{ xor } K = M_1 \text{ xor } M_2$, since $K \text{ xor } K = 0$, so the key cancels and does not protect anything.

</details>

**6. (Simulate)** Simulate the alarm of problem 3 with 5,000,000 events and compare $P(\text{attack} \mid \text{alarm})$ with the exact value.

<details>
<summary>Answer</summary>

```python
import numpy as np

rng = np.random.default_rng(42)
n_events = 5_000_000

# 1 event in 10,000 is an attack. The alarm fires for 99% of attacks and for 1% of normal events.
is_attack = rng.random(n_events) < 0.0001
alarm = rng.random(n_events) < np.where(is_attack, 0.99, 0.01)
print(f"P(attack | alarm): simulation {is_attack[alarm].mean():.4f}, exact {0.000099 / (0.000099 + 0.009999):.4f}")
```

Output:

```text
P(attack | alarm): simulation 0.0097, exact 0.0098
```

The attacks are rare, so even 5 million events contain only about 500 of them. The estimate is noisy in the third digit.

</details>

## Summary

- A uniform $b$-bit key is guessed with probability $2^{-b}$ per try. After $g$ different guesses the chance is $\frac{g}{2^b}$, and the expected number of guesses is $\frac{2^b + 1}{2}$. Each extra bit doubles the work.
- The one-time pad $C = M \text{ xor } K$, with $K$ uniform, independent of $M$ and used once, has perfect secrecy: $P(M = m \mid C = c) = P(M = m)$. A reused key gives $C_1 \text{ xor } C_2 = M_1 \text{ xor } M_2$.
- A key or password that is not uniform is weaker than its length suggests. Its strength is measured by the expected rank $\sum i \thinspace p_{(i)}$ of the best attack.
- Seeds of simulations are not secrets, and a short seed means a short key.
- Collisions of hash values come at about $2^{b/2}$ tries. Alarms with rare attacks need Bayes' theorem and the base rate.

The one formula to remember:

$$
\boxed{P(C = c \mid M = m) = P(K = m \text{ xor } c) = 2^{-b} \quad \text{for every } m \text{ and } c}
$$
