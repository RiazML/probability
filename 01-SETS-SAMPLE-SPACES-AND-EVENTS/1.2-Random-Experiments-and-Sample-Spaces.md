# 1.2 Random Experiments and Sample Spaces

[Probability](../README.md) / [Module 01: Sets, Sample Spaces and Events](README.md) / 1.2 Random Experiments and Sample Spaces

**Level:** 1 (Zero) · **Time:** about 35 minutes · **Before this:** [1.1 What is Probability](1.1-What-is-Probability.md)

> **Big idea:** Before you compute any probability, write down the sample space: the set of every outcome the experiment can produce.

---

## Why It Matters

In [1.1 What is Probability](1.1-What-is-Probability.md) we counted "outcomes" without saying
exactly what an outcome is. The two-dice trap (Example 3 there) showed that the choice of
outcomes can change the answer. A **sample space** makes the list of outcomes exact. Events,
the axioms, random variables and every later idea in this book are built on top of it.

## Intuition

You roll two dice, one red and one blue. What can happen? The red die shows a number from 1
to 6, and so does the blue die. So one result is a pair, such as "red 3, blue 5". There are
6 choices for red and 6 for blue, so there are 36 pairs. Every roll gives exactly one of
them.

You could also write down only the sum. Then there are just 11 results, from 2 to 12. That
list is not wrong, but it hides detail: the sums are **not** equally likely, so you cannot
count them. The 36 pairs **are** equally likely, so you can. The same physical experiment
can have different sample spaces. It depends on what you choose to record.

A good list of outcomes passes two tests:

- **Nothing is missing.** Every run of the experiment gives some result on the list.
- **Nothing overlaps.** Every run gives exactly one result on the list, never two.

A weather list like "sunny, rainy, windy" fails both tests. A cloudy, calm day is missing.
A rainy, windy day fits two items at once.

## Picture

```text
                              Blue die
                1      2      3      4      5      6
           +-------------------------------------------
         1 |  (1,1)  (1,2)  (1,3)  (1,4)  (1,5)  (1,6)
         2 |  (2,1)  (2,2)  (2,3)  (2,4)  (2,5)  (2,6)
   Red   3 |  (3,1)  (3,2)  (3,3)  (3,4)  (3,5)  (3,6)
   die   4 |  (4,1)  (4,2)  (4,3)  (4,4)  (4,5)  (4,6)
         5 |  (5,1)  (5,2)  (5,3)  (5,4)  (5,5)  (5,6)
         6 |  (6,1)  (6,2)  (6,3)  (6,4)  (6,5)  (6,6)

   One roll of both dice  --->  exactly ONE cell  --->  one outcome ω
```

The sample space of two dice: 36 cells, one for each ordered pair (red, blue).

## Definition

A **random experiment** is a process that we can repeat (at least in our minds), whose
possible results we can describe in advance, but whose actual result we cannot predict
for sure. Rolling a die, sending a network packet and asking a random person a question are
all random experiments.

An **outcome**, written $\omega$ (the Greek letter omega), is one complete result of one run
of the experiment.

The **sample space**, written $\Omega$ (capital omega), is the set of all possible outcomes:

$$
\Omega = \lbrace \text{all possible outcomes of the experiment} \rbrace
$$

It must have two properties:

- **Exhaustive:** every run produces some outcome in $\Omega$. Nothing is missing.
- **Exclusive:** every run produces exactly one outcome in $\Omega$. No two outcomes can
  happen in the same run.

**In words:** the sample space is a complete list of things that can happen, where each
run of the experiment picks exactly one item from the list.

We write $\omega \in \Omega$ ("omega is in Omega") to say that $\omega$ is one of the
outcomes. When $\Omega$ is finite, $\lvert \Omega \rvert$ means the **size** of
$\Omega$: the number of outcomes in it.

Sample spaces are sets, so we write them with braces. A short list is written out in full.
A long one uses **set-builder notation**, $\lbrace \text{pattern} : \text{condition} \rbrace$,
read as "the set of all things of this pattern such that the condition holds".

| Experiment | Sample space | Size |
|---|---|---|
| Flip a coin | $\lbrace H, T \rbrace$ | 2 |
| Roll a die | $\lbrace 1, 2, 3, 4, 5, 6 \rbrace$ | 6 |
| Flip a coin 3 times | $\lbrace HHH, HHT, HTH, HTT, THH, THT, TTH, TTT \rbrace$ | 8 |
| Roll two dice | $\lbrace (i, j) : i, j \in \lbrace 1, \dots, 6 \rbrace \rbrace$ | 36 |
| Count emails arriving in one hour | $\lbrace 0, 1, 2, 3, \dots \rbrace$ | infinite |
| Time (in seconds) until a light bulb fails | $[0, \infty)$ | infinite |

The last two lists never end. Topic
[1.9 Finite, Countable and Uncountable Spaces](1.9-Finite-Countable-and-Uncountable-Spaces.md)
explains the two kinds of infinity you see here.

## Why It Is True

**Why two dice give 36 outcomes.** Count the grid in the picture row by row. Each value of
the red die starts one row, and each row has one cell for each value of the blue die:

$$
\begin{aligned}
\lvert \Omega \rvert &= 6 + 6 + 6 + 6 + 6 + 6 && \text{(6 rows, one per red value)} \\
&= 6 \times 6 && \text{(each row has 6 cells)} \\
&= 36
\end{aligned}
$$

**Why $n$ coin flips give $2^n$ outcomes.** Let $\Omega_n$ be the sample space for $n$
flips. Every sequence of $n - 1$ flips can be finished in exactly two ways: add an H or add
a T. Different short sequences give different long ones. So each extra flip doubles the
count, and one flip has 2 outcomes:

$$
\lvert \Omega_n \rvert = 2 \lvert \Omega_{n-1} \rvert = 2^2 \lvert \Omega_{n-2} \rvert = \dots = 2^{n-1} \lvert \Omega_1 \rvert = 2^n
$$

For $n = 3$ this gives $2^3 = 8$, which matches the table. Both counts are cases of the
**multiplication rule**, which [2.1 Multiplication and Addition Rules](../02-COUNTING/2.1-Multiplication-and-Addition-Rules.md)
treats in general.

**Why both properties are needed.** The counting rule from 1.1 divides by the number of
outcomes. If an outcome is missing, a run can produce something we never counted. If two
outcomes overlap, one run is counted twice. Either way the fractions no longer describe
what really happens.

## Worked Examples

### Example 1: Three Coin Flips

**Problem.** You flip a fair coin 3 times. Write the sample space. What is the probability
of exactly two heads?

**Solution.**

1. Record the result of each flip, in order. Each outcome is a string of 3 letters:

$$
\Omega = \lbrace HHH, HHT, HTH, HTT, THH, THT, TTH, TTT \rbrace
$$

2. The size is $\lvert \Omega \rvert = 2^3 = 8$. The coin is fair, so the 8 strings are
   equally likely.
3. The outcomes with exactly two heads are HHT, HTH and THH. That is 3 outcomes.
4. Use the counting rule:

$$
P(\text{exactly two heads}) = \frac{3}{8} = 0.375
$$

**Answer.** $P(\text{exactly two heads}) = 0.375$.

**Check.** By symmetry, exactly two tails must also have probability $\frac{3}{8}$. The
other two cases, HHH and TTT, have $\frac{1}{8}$ each. The total is
$\frac{3}{8} + \frac{3}{8} + \frac{1}{8} + \frac{1}{8} = 1$, as it must be.

### Example 2: Hashing Two Keys

**Problem.** A hash table has 3 buckets, numbered 0, 1 and 2. A good hash function sends
each key to a bucket at random, and the bucket of one key has no effect on the bucket of
the other. You insert two keys. What is the sample space, and what is the probability of a
**collision** (both keys in the same bucket)?

**Solution.**

1. An outcome must say where **each** key went. So an outcome is an ordered pair
   (bucket of key 1, bucket of key 2):

$$
\Omega = \lbrace (0,0), (0,1), (0,2), (1,0), (1,1), (1,2), (2,0), (2,1), (2,2) \rbrace
$$

2. There are $3 \times 3 = 9$ outcomes, and under our assumption they are equally likely.
3. A collision happens in $(0,0)$, $(1,1)$ and $(2,2)$: 3 outcomes.

$$
P(\text{collision}) = \frac{3}{9} = \frac{1}{3} \approx 0.333
$$

**Answer.** About 1 in 3. Even a tiny table with only two keys collides often.

**Check.** Whatever bucket key 1 lands in, key 2 has 1 chance in 3 to land in the same
one. The simulation below agrees.

### Example 3: Is It a Valid Sample Space

**Problem.** For one roll of a die, which of these lists are valid sample spaces?

- (a) $\lbrace 1, 2, 3, 4, 5, 6 \rbrace$
- (b) $\lbrace \text{even}, \text{odd} \rbrace$
- (c) $\lbrace 1, 2, 3, 4, 5 \rbrace$
- (d) $\lbrace \text{low (1 to 3)}, \text{high (4 to 6)}, \text{six} \rbrace$

**Solution.**

1. List (a) contains every face once. It is exhaustive and exclusive. **Valid.**
2. List (b): every roll is even or odd, never both. **Valid**, but less detailed. It
   cannot answer "did I roll a 6?".
3. List (c): a roll of 6 is not on the list. Not exhaustive. **Not valid.**
4. List (d): a roll of 6 is both "high" and "six". Not exclusive. **Not valid.**

**Answer.** Lists (a) and (b) are valid sample spaces. Lists (c) and (d) are not.

**Check.** A useful habit: take each possible roll and ask "which item on the list is
this?". There must be exactly one answer every time.

## Simulate It

The code builds the sample space of Example 2 by listing every pair, counts the collisions,
and then runs the experiment 100,000 times.

```python
import itertools
import numpy as np

rng = np.random.default_rng(42)
n_trials = 100_000

# The sample space: every pair (bucket of key 1, bucket of key 2).
omega = list(itertools.product([0, 1, 2], repeat=2))
collisions = [w for w in omega if w[0] == w[1]]
exact = len(collisions) / len(omega)
print(f"Size of the sample space: {len(omega)}")
print(f"Outcomes with a collision: {collisions}")

# Run the experiment: each key lands in one of the 3 buckets at random.
key1 = rng.integers(0, 3, size=n_trials)
key2 = rng.integers(0, 3, size=n_trials)
estimate = np.mean(key1 == key2)

print(f"Simulation: {estimate:.4f}")
print(f"Exact:      {exact:.4f}")
```

Output:

```text
Size of the sample space: 9
Outcomes with a collision: [(0, 0), (1, 1), (2, 2)]
Simulation: 0.3312
Exact:      0.3333
```

Listing the sample space in code (with `itertools.product`) is a good habit. For small
experiments it gives exact answers, which you can then compare with a simulation.

## Common Mistakes

- **Recording too little.** Writing only the sum of two dice gives 11 outcomes that are not
  equally likely. Record enough detail (the ordered pair) so that you can count.
- **Forgetting order.** $(1,2)$ and $(2,1)$ are different outcomes, even if the two dice
  look the same. The dice do not know their colors: "a 1 and a 2" really happens in two
  ways.
- **Lists with gaps or overlaps.** Check every sample space with the two tests: nothing
  missing, nothing counted twice.
- **Mixing up an outcome and a question about it.** "Even" is not an outcome of a die. It is
  a group of outcomes, called an event. That is the next topic,
  [1.3 Events as Subsets](1.3-Events-as-Subsets.md).
- **Hidden assumptions.** A coin can land on its edge. We usually agree to ignore this.
  Say such choices out loud when you write the sample space.

## Where It Is Used

- **AI and machine learning:** a classifier's outputs live in a sample space of labels,
  such as $\lbrace \text{cat}, \text{dog}, \text{bird} \rbrace$. A language model picks
  the next token from a sample space of tens of thousands of tokens.
- **Computer science:** hash tables, randomized algorithms and load balancers are
  analyzed by writing down where every key, pivot or request can go.
- **Networks:** a packet sent over a link is delivered or lost; a request's response time
  is a number of milliseconds. Both are sample spaces that engineers model.
- **Testing software:** the sample space of inputs tells you what a random test can
  generate, and what it can never reach.
- **Everyday life:** before you judge a risk, list what can actually happen. Many bad
  decisions come from a missing outcome.

## Practice

**1. (Easy)** You flip a coin and roll a die. Write the sample space. How many outcomes
does it have?

<details>
<summary>Answer</summary>

Each outcome is a pair (coin, die):

$$\Omega = \lbrace (H,1), (H,2), \dots, (H,6), (T,1), (T,2), \dots, (T,6) \rbrace$$

There are $2 \times 6 = 12$ outcomes.

</details>

**2. (Easy)** A cricket match can end in a win, a loss, a draw, a tie or no result. Is
$\lbrace \text{win}, \text{loss}, \text{draw}, \text{tie}, \text{no result} \rbrace$ a valid
sample space for the match, seen from one team? Can you use the counting rule on it?

<details>
<summary>Answer</summary>

Yes, it is valid: every match ends in exactly one of these five ways. But you cannot use
the counting rule, because the five outcomes are not equally likely. A tie is much rarer
than a win or a loss. So the answer is not $\frac{1}{5}$ for each.

</details>

**3. (Medium)** A student guesses the answers to 3 true/false questions. Write the sample
space. What is the probability that all 3 answers are right? That at least 2 are right?

<details>
<summary>Answer</summary>

Write R for right and W for wrong. The sample space has $2^3 = 8$ equally likely strings:
RRR, RRW, RWR, RWW, WRR, WRW, WWR, WWW. All right is only RRR. At least 2 right is RRR,
RRW, RWR and WRR:

$$P(\text{all right}) = \frac{1}{8} = 0.125, \qquad P(\text{at least 2 right}) = \frac{4}{8} = 0.5$$

</details>

**4. (Medium)** A box has 3 balls: red (R), green (G) and blue (B). You draw one ball, do
**not** put it back, and draw a second. Write the sample space of ordered pairs. What is the
probability that the red ball is drawn? How does the answer change if you put the first
ball back before the second draw?

<details>
<summary>Answer</summary>

Without putting it back, the two balls differ:
$\Omega = \lbrace RG, RB, GR, GB, BR, BG \rbrace$, 6 equally likely outcomes. Red appears in
RG, RB, GR, BR:

$$P(\text{red drawn}) = \frac{4}{6} = \frac{2}{3}$$

With putting it back, there are $3 \times 3 = 9$ pairs, now including RR, GG, BB. Red
appears in RR, RG, RB, GR, BR:

$$P(\text{red drawn}) = \frac{5}{9} \approx 0.556$$

</details>

**5. (Hard)** You flip a fair coin until you see a head, but you stop after 3 flips no
matter what. Write the sample space. Are its outcomes equally likely? Find the probability
of each one.

<details>
<summary>Answer</summary>

The possible records are $\Omega = \lbrace H, TH, TTH, TTT \rbrace$. They are **not**
equally likely. To see why, imagine you always flip 3 times and just ignore the flips after
the first head. Then there are 8 equally likely strings of 3 flips. The outcome H covers the
4 strings that start with H. TH covers THH and THT. TTH and TTT cover one string each:

$$P(H) = \frac{4}{8} = \frac{1}{2}, \quad P(TH) = \frac{2}{8} = \frac{1}{4}, \quad P(TTH) = \frac{1}{8}, \quad P(TTT) = \frac{1}{8}$$

The four answers add up to 1, as they must.

</details>

**6. (Simulate)** Write code that runs the experiment of Problem 5 100,000 times and
estimates the probability of each outcome.

<details>
<summary>Answer</summary>

```python
import numpy as np

rng = np.random.default_rng(42)
n_trials = 100_000
flips = rng.integers(0, 2, size=(n_trials, 3))   # 1 = head, 0 = tail

# Outcome: flip number of the first head (1, 2, 3), or 0 for TTT.
first_head = np.where(flips.any(axis=1), flips.argmax(axis=1) + 1, 0)
for k, name, exact in [(1, "H", 1 / 2), (2, "TH", 1 / 4),
                       (3, "TTH", 1 / 8), (0, "TTT", 1 / 8)]:
    print(f"{name:>3}: simulation {np.mean(first_head == k):.4f}, exact {exact:.4f}")
```

Output:

```text
  H: simulation 0.4986, exact 0.5000
 TH: simulation 0.2510, exact 0.2500
TTH: simulation 0.1259, exact 0.1250
TTT: simulation 0.1245, exact 0.1250
```

</details>

## Summary

- A random experiment has results we can list but cannot predict.
- An outcome $\omega$ is one complete result. The sample space $\Omega$ is the set of all
  outcomes.
- A valid sample space is exhaustive (nothing missing) and exclusive (no overlaps).
- You choose how much detail to record. Choose enough to answer your question, and if
  possible choose outcomes that are equally likely.
- Ordered pairs and strings are the usual outcomes for experiments with several steps.

The one formula to remember (two dice, the most used sample space in this module):

$$
\boxed{\Omega = \lbrace (i, j) : i, j \in \lbrace 1, \dots, 6 \rbrace \rbrace, \qquad \lvert \Omega \rvert = 6 \times 6 = 36}
$$
